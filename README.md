# Opus Android

This project contains the Opus 1.5.2 source code and a build script for building Opus as Android libraries.

Upstream repository: https://github.com/xiph/opus

## Build Environment

Example build environment:

- macOS (the build script only supports macOS hosts)
- Android NDK: r28c
- Opus: 1.5.2

You may replace the versions above according to your local environment.

## Supported Architectures

- armeabi-v7a
- arm64-v8a

## Build Instructions

The whole build is done by `build_opus_android.sh` in the project root. You only need to adjust a few settings in the script and run it.

### 1. Configure the Build Script

Open `build_opus_android.sh` and update the following variables at the top of the file:

```bash
NDK=/Users/anathan/Documents/android-ndk-r28c   # Path to the Android NDK on your machine
API=21                                          # Minimum Android API level (minSdk) of the libraries
OUTPUT_SO_NAME="librtk-audio-toolbox.so"        # File name of the generated shared library
```

- `NDK`: **Must** be changed to the Android NDK path on your machine, e.g. `/Users/yourname/Library/Android/sdk/ndk/28.2.xxxxxxx`.
- `API`: The minimum Android API level of the generated libraries. It should not be higher than the `minSdk` of the app that uses them.
- `OUTPUT_SO_NAME`: The name of the generated shared library. Keep the default value unless the project that uses the library loads it with a different name.

To build only one ABI, edit the `ARCHS` array in the script.

The script uses the NDK LLVM toolchain in `$NDK/toolchains/llvm/prebuilt/darwin-x86_64`. The script does not check this path in advance, so an incorrect `NDK` path will cause `configure` to fail with a "C compiler cannot create executables" error.

### 2. Grant Execute Permission

```bash
chmod +x build_opus_android.sh
```

### 3. Build Libraries

The script must be run **from the project root**, because it uses the current directory as the Opus source directory:

```bash
cd /path/to/opus-1.5.2
./build_opus_android.sh
```

## Build Output

After a successful build, the output is located in the `android/build/` directory of the project root:

```text
android/build/
├── armeabi-v7a/
│   ├── include/
│   │   └── opus/
│   │       ├── opus.h
│   │       ├── opus_defines.h
│   │       ├── opus_multistream.h
│   │       ├── opus_projection.h
│   │       └── opus_types.h
│   ├── lib/
│   │   ├── librtk-audio-toolbox.so
│   │   ├── libopus.a
│   │   ├── libopus.la
│   │   └── pkgconfig/
│   │       └── opus.pc
│   └── share/
│       └── aclocal/
│           └── opus.m4
└── arm64-v8a/
    └── (same layout as armeabi-v7a)
```

- `lib/librtk-audio-toolbox.so`: Shared library, linked from `libopus.a`. This is the library used by the Android project.
- `lib/libopus.a`: Static library.
- `include/opus/`: Public headers.
- `lib/libopus.la`, `lib/pkgconfig/opus.pc`, `share/aclocal/opus.m4`: libtool / pkg-config / autoconf metadata. Not needed for Android integration.

## Notes

- The script runs `make distclean` before building each ABI, which removes the files generated by `configure` (`config.h`, `Makefile`, etc.) in the source root. This is expected.
- The output directory is **not** cleaned before building. If you change `OUTPUT_SO_NAME` or `ARCHS`, delete `android/build/` first to avoid leftover files.
- Do not delete the original `README`, `NEWS`, `AUTHORS` and `ChangeLog` files. They are required by Automake.
